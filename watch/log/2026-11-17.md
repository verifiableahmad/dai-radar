- **arXiv 2611.21590, "The Provenance-Privacy Paradox: Can Private
  Cloud Compute (PCC) Prove That Apple Reference Images Are Not Used
  for Learning?", checked against systems/apple-private-cloud-compute.md
  (no edit):** a position paper with a Python/Docker testbed that
  models Apple Reference Image and PCC functions. It does not run on
  production PCC. Its argument is that workload attestation and
  transparency-log inclusion verify which software runs, not that the
  software cannot learn from or keep the data. In the testbed, a
  learning workload passed the same checks and returned byte-identical
  JPEGs while keeping a gradient from which the input could be
  rebuilt. The authors state that this does not show that Apple trains
  on the photos. The Confidentiality axis restates Apple's own
  "stateless, no retention" claim, and the paper does not contradict
  it. It argues that attestation alone cannot prove the claim. Read
  from the abstract only. No row changes. This is the second
  third-party PCC critique in three runs, after ePrint 2026/2875 on
  2026-11-15. The file's Known limitations says to watch for exactly
  this, so a manual read of both papers is worth doing before any
  limitation is added.

### Related, not yet tied to a tracked system

- **RRHL: a relational logic for Rényi DP of private learning**
  (ePrint 2026/2881): a program logic, formalized in Lean, that proves
  Rényi-DP bounds for DP-SGD and DP-FTRL variants and for per-record
  Rényi filters, in several cases matching the best known analyses.
  Field: differential privacy. It verifies algorithms, not Opacus's
  code, so systems/opacus.md is unchanged.
- **Batch, Pack, and Prove: verifiable computation for CKKS** (ePrint
  2026/2878): builds on Cascudo et al. (CRYPTO 2025) with a new
  polynomial commitment (BatchFold) and packing techniques. It reports
  proofs "several orders of magnitude smaller and faster" on a generic
  neural network. Field: FHE for ML plus integrity. No tracked system
  uses it.
- **Rethinking the verification of machine unlearning** (arXiv
  2611.18658): an attack (ODR) that passes output-based unlearning
  verifiers about 97% of the time while the model's representations
  stay the same, plus a gray-box verifier (RUV) that compares internal
  representations. Field: verifiable unlearning (statistical, not
  cryptographic). No tracked system uses it.
- **NoCherry: verifiable random sampling of private data** (arXiv
  2611.21222): commit to item hashes with independent servers, then let
  a decentralized randomness beacon pick the sample, so auditors can
  check that a revealed sample of a private benchmark was not
  cherry-picked. Field: verifiable evaluation. No tracked system uses
  it.
